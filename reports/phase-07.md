# Phase 07 — Reliable Unattended Operation

Date: 2026-11-18–19 (America/Los_Angeles)

Status: PARTIALLY VERIFIED. The user LaunchAgent, protected worker recovery, crash restart throttle, reminder delivery after controller recovery, live browser task, and Telegram task controls passed. Real owner logout/login and reboot recovery were not performed, so automatic login recovery is not claimed. A live unauthorized-account callback test was not performed.

## Changes

- Added `ops/macos/install-controller-launch-agent.sh` and `ops/macos/uninstall-controller-launch-agent.sh` for a per-user `com.toothless.telegram-controller` LaunchAgent. It starts the repository virtual environment on Aqua login, uses KeepAlive with a 30-second restart throttle, passes only the protected env-file path, and writes bounded owner-only logs. Installation refuses an already-running manual controller.
- Added an owner-private singleton lock at `~/.local/share/toothless/telegram/controller.lock`, held for the controller lifetime. A second poller cannot acquire it. The controller log rotates at 2 MB with three retained backups under mode-0700 storage.
- Added a protected Softnet launcher heartbeat, published only after policy acknowledgement, relay readiness, and guest DNS verification. The read-only readiness probe checks the current heartbeat, Softnet state, relay, guest DNS, root-owned execution helper, guest-local OpenCode Go authentication metadata, and reviewed workspace/browser profiles. It does not read secret values, start/reset the VM, or transfer credentials.
- The SSH worker provider fails closed unless the VM has fresh verified protected-launch evidence. Direct Tart startup remains unprotected.
- Updated `ops/worker/shutdown.sh` to retrieve the current guest SSH host key through Tart, use a temporary owner-only known-hosts file with strict verification, disable agent use/forwarding, and fail rather than ignoring SSH errors. The pin is ephemeral; no persistent host trust or VM configuration is changed.
- `/status` renders host-owned controller, worker, schedule, task, failure, and last-success information with Refresh, Tasks, Schedules, and Diagnostics controls. Consequential callbacks remain owner/chat/message/expiry bound and are checked against authoritative state.

## Operator notes

Use the LaunchAgent installer/remover in `ops/macos/` for controller lifecycle management. If worker readiness is missing or stale, do not start Tart directly; use `ops/worker/start.sh` and require all readiness fields to pass. After a VM reset, restore the documented helper/runtime and authenticate interactively inside Ubuntu; never copy Mac credentials or reseal the baseline as a readiness repair. The controller does not auto-start/reset the worker. Memory Explorer remains separate and optional.
