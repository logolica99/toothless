## Architecture selected

The stable view-only guest display is Xvfb at fixed display `:99`, Openbox, and xterm under the dedicated `toothless-desktop` system identity. Firefox 160.0.1 is installed at `/opt/toothless/firefox` and its version is verified, but Firefox GUI content processes crashed under the reviewed 128-task unit ceiling; the binary is therefore not launched by the stable view-only session. A separate bounded Firefox headless smoke exited successfully and produced a valid PNG, though one auxiliary child emitted a SIGSEGV diagnostic. The systemd unit retains its approved 1 GiB memory, 150% CPU, 128 tasks, and 256 open-file limits; it enables `PrivateTmp`, `PrivateDevices`, `ProtectSystem=strict`, `ProtectHome`, and other hardening. Xvfb uses a 0700 socket directory inside its private temp namespace and `-nolisten tcp`. The ordinary OpenCode browser remains a separate headless process/profile and is not visible on this desktop.

I selected the virtual display instead of Tart's host-facing graphical console so screenshots originate only in Ubuntu and no host screen is involved. I did not select VNC/noVNC because a desktop protocol endpoint or WebSocket proxy adds input and network surface that this phase does not need. The browser viewer is an image-polling page; the server has no keyboard, mouse, clipboard, upload, file-transfer, or WebSocket route. Mozilla's Linux AArch64 Firefox 160.0.1 archive was accepted only after signature and checksum verification against the signed manifest.

The root-owned fixed guest helper accepts only `desktop_screenshot`, `desktop_status`, `start_desktop`, and `stop_desktop` requests and rejects additional fields. Screenshot capture uses the fixed display and `scrot`, is capped at 4 MiB and 1280×800, and returns only PNG bytes through the existing strict pinned-key SSH protocol. Since the systemd service uses a private temporary namespace, the screenshot helper joins only that service's mount namespace before running `scrot` as the desktop identity. The host never supplies a guest path, command, display, or URL.

Telegram `/desktop` is owner/private-chat only. Its one-use callback records bind action to owner, chat, source message, and expiry. Screenshot requests require fresh protected worker readiness and send a new Telegram photo; Open Desktop starts only the fixed guest desktop unit after readiness, not the VM; Close Viewer revokes the token and requests the fixed desktop stop. The optional host viewer binds to `127.0.0.1:8769`, creates a one-use local code in an owner-private file, exchanges it once for a short HttpOnly/SameSite cookie, and polls bounded PNG images every two seconds for at most ten minutes. It uses a per-response CSP nonce and has no guest input endpoint. A controller restart invalidates stale local codes.

The viewer is local to the Mac Mini. An iPhone cannot reach a Mac loopback listener through Telegram, so off-network viewing remains NOT RUN and unsupported. A separately approved private HTTPS access transport would be needed; no VPN, tunnel, router port, public ingress, firewall, Softnet policy, or remote endpoint was added.

## Implementation fixes made

- The viewer now uses a per-response CSP nonce instead of inline-script permission, rejects duplicate HTTP headers and transfer encoding, validates image signature and dimensions at the server boundary, and creates its one-use token with owner-only exclusive file creation while rejecting symlinked token directories.
- Fixed a revocation deadlock: the HTTP handler previously waited for the viewer server to finish closing while its own request was still active. It now invalidates the token and listener immediately, responds, then completes listener shutdown after the request handler exits.
- The guest helper now reports a missing `toothless-desktop` identity as an explicit unavailable result. Screenshot capture joins the systemd unit mount namespace because `PrivateTmp=yes` isolates its X11 Unix socket.
- Worker protocol, Telegram callbacks, fixed guest operation names, and screenshot validation remain bounded; no general shell tool or execution permission was added.
