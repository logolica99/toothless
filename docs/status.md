## Phase 05.4 — Telegram file input/output

The local implementation now accepts owner-only PDF, TXT, CSV, JSON, PNG/JPG, and small ZIP uploads. It limits each incoming file to 512 KiB, ZIP expansion to 2 MiB and 12 entries, and owner-private staged storage to 50 MiB. ZIP members are validated in memory without extracting user-controlled paths onto the Mac. Host SQLite records store the task/file association and metadata; opaque file contents remain in the private host attachment directory until the owner explicitly approves `/run`. The workspace profile then copies them through the existing pinned-key worker interface into `opencode-task-workspace/inputs/<task_id>/`; the browser-only profile refuses attached tasks. Guest output is collected only from `opencode-task-workspace/exports/<task_id>/`, with per-file and aggregate limits and persisted one-shot Telegram delivery state. Staged inputs are admin-owned mode 0644 inside the restricted OpenCode workspace so the rootless OpenCode identity can read them.

Local verification now passes 79 focused tests, Ruff, BasedPyright, import-boundary checks, worker static checks, and `git diff --check`. The first real upload, task `task-6a7bdc1eb955983728d9522b53086306`, failed before OpenCode started because the guest helper attempted a non-root `fchown`; the fix was deployed and validated with a pinned-key guest probe. The second upload task `task-9c02c6129e8528421526a4e8683d4088` timed out at 120 seconds without exports. A third task, `task-bc2af8391f32de8ec4d582cfcd9263ac`, ran to the 300-second attachment limit, but its guest workspace contained `chart.png` and `summary.csv`. I independently verified both files against the uploaded CSV, persisted a partial result while retaining the task's failed status, and delivered the files to Telegram (message IDs 323 and 324) with a recovery update (message 326); the owner confirmed the recovery worked. After controller restart, TaskStore still showed the failed status, partial result, and delivered message IDs; no OpenCode process remained. The controller now sends status-only running updates once per minute. Hard timeouts remain in place; removing every execution limit would let a stuck process occupy the sole runner indefinitely. Further live run/progress testing remains NOT RUN. Do not mark Phase 05.4 verified until remaining acceptance and regression checks pass. Uploaded data read by OpenCode may be sent to the selected OpenCode Go model as part of the approved inference path; public guest egress and guest-local provider credential exposure remain existing trust-domain risks. See `reports/phase-05-04.md` and `docs/file-security.md`.
